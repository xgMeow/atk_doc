# Chain

## Functional Description

The objects in a chain are connected in the order given in the "Assigned Objects" list, and adjacent objects form one segment. Only when all segments satisfy the access condition at the same instant does that instant constitute a valid interval of the complete chain.

A chain can be used to describe a continuous access path composed of multiple objects. For example, a direct communication chain from a transmitter to a receiver can be established, and relay-related objects can be added in turn according to the mission topology to form a multi-segment continuous chain.

> **Note**: The order of the objects in a chain is of practical significance. When the same set of objects is arranged in a different order, it represents a different access path, so the objects should be configured according to the actual transfer order of the signal, data, or mission relationship.

## Definition

### Selection Filter

The **option filter** is used to filter the "Available Objects" list by object type. After an object type is checked, objects of that type can be highlighted in the object tree below; after it is unchecked, objects of that type are no longer displayed as the result of the current filter.

| Interface Item | Description |
|---|---|
| Object type box | Controls the content displayed in the "Available Objects" list by object type, including satellites, antennas, receivers, transmitters, etc. |
| Select all filters | Checks all object type filters, displaying all object types that can be used for chain definition. |
| Clear all filters | Unchecks all object type filters. |

> **Note**: The object selection filter only affects "Available Objects" and does not change the chain definition already added to the "Assigned Objects" list.

### Available Objects

**Available Objects** displays in a tree structure the objects in the current scenario that can participate in the calculation. Parent objects and their child objects are expanded and displayed according to the scenario hierarchy; for example, a satellite object may contain communication child objects such as antennas, receivers, and transmitters.

After selecting the objects to be added to the chain, click the right arrow in the middle to add the objects to the 【Assigned Objects】 list on the right.

### Assigned Objects

**Assigned Objects** gives the objects contained in the current chain and their order.

| Operation | Description |
|---|---|
| Right arrow | Adds the object selected on the left to the **Assigned Objects** list. |
| Left arrow | Removes the object selected on the right from the chain. |
| Up arrow | Moves the selected object forward in the chain order. |
| Down arrow | Moves the selected object backward in the chain order. |

Suppose $n$ objects are selected in sequence in the chain:

$$
O_1\rightarrow O_2\rightarrow\cdots\rightarrow O_n
$$

Then the software checks the access relationship between adjacent objects in order:

$$
O_1\leftrightarrow O_2,
\quad
O_2\leftrightarrow O_3,
\quad\ldots\quad,
O_{n-1}\leftrightarrow O_n
$$

Therefore, changing the order in **Assigned Objects** changes the connection relationship of the chain.

### Valid Intervals of the Chain

The validity of a chain is determined jointly by the valid intervals of the connections between adjacent objects. Let the set of valid intervals of the $i$-th segment $O_i\rightarrow O_{i+1}$ be $I_i$; then the valid intervals of the complete chain are the intersection of the valid intervals of all segments:

$$
I_{\mathrm{Chain}}
=
\bigcap_{i=1}^{n-1} I_i
$$

This can also be expressed by a logical test. Let $A_i(t)$ indicate whether the $i$-th segment is valid at time $t$; then:

$$
C_{\mathrm{Chain}}(t)
=
\bigwedge_{i=1}^{n-1} A_i(t)
$$

Only when all adjacent connections are valid at the same instant:

$$
C_{\mathrm{Chain}}(t)=1
$$

does that instant belong to the valid intervals of the complete chain.

For example, for a three-object chain:

$$
A\rightarrow B\rightarrow C
$$

both $A$ and $B$ being accessible and $B$ and $C$ being accessible must be satisfied simultaneously to form a complete chain from $A$ to $C$. If any segment is interrupted, the complete chain is unavailable at that instant.

> **Note**: The chain calculation focuses on whether the entire continuous path holds. The existence of an access between a pair of objects does not mean that the complete chain is necessarily valid; the other adjacent connections in the chain must also hold at the same instant.

### Object Order in a Communication Chain

When a chain is used for communication analysis, the object order should be set according to the actual signal or data transfer direction. A typical direct communication path can be expressed as:

$$
\mathrm{Transmitter}
\rightarrow
\mathrm{Receiver}
$$

When a relay exists, the objects related to the uplink end, the forwarding end, and the downlink end can be organized in turn according to the actual communication model. The chain definition is responsible for establishing the continuous object relationship, while the parameters of each communication segment, such as EIRP, propagation loss, receiving antenna gain, $G/T$, $C/N_0$, $C/N$, $E_b/N_0$, and bit error rate, are determined by the corresponding communication model and link calculation function.

> **Note**: If both a parent object and its communication child objects are selected in a chain, the order should be determined according to the actual analysis purpose, and should not be arranged solely on the basis of the parent-child relationship in the object tree.

## Display

Used to control how the chain is displayed in the graphics window, including the overall display toggle, static visualization, and dynamic visualization.

### Display

The **Display** at the top is used to control the overall display state of the chain graphics. It enables or disables the display of chain graphics. Once disabled, the static and dynamic graphics configured on this page are no longer displayed.

### Static Visualization

Static visualization is used to display the object connection relationship obtained from the chain calculation in a fixed graphic style, making it easy to view the objects and connections involved in the chain when animation is not running.

| Parameter | Description |
|---|---|
| Display | Enables the static chain graphics. |
| Color | Sets the display color of the static chain graphics. |
| Line Style | Sets the line style of the static chain graphics. |
| Line Width | Sets the line width of the static chain graphics. |

Static visualization is mainly used to identify the chain relationship as a whole; its display does not emphasize the instantaneous access state at the current animation time.

> **Note**: Static graphics represent the overall relationship between the chain objects. To observe whether the chain is currently connected at a certain animation time, use dynamic visualization.

### Dynamic Visualization

Dynamic visualization is used to display the chain state at the current time along with the scenario animation. When the chain is valid at the current time, the currently valid connections can be displayed intuitively through object highlighting and connection lines.

| Parameter | Description |
|---|---|
| Show Highlight | Highlights the corresponding object when a chain object currently participates in a valid connection. |
| Show Line | Displays a dynamic connection line between adjacent objects that are currently valid. |
| Color | Sets the display color of the dynamic chain lines. |
| Line Style | Sets the line style of the dynamic chain lines. |
| Line Width | Sets the line width of the dynamic chain lines. |
| Show Direction | Displays the direction or order identifier of the chain connections, used to identify the sequence of the segments in the chain. |

Dynamic chain lines only reflect the valid connections at the current animation time, so as time advances, the connection lines and highlighted objects may appear, disappear, or change.

When 【Show Direction】 is enabled, the direction/order information on the chain lines can be used to determine the connection sequence of the chain. For example, for:

$$
A\rightarrow B\rightarrow C
$$

the direction display is used to distinguish the sequence relationship between the two segments $A\rightarrow B$ and $B\rightarrow C$.

> **Note**: Dynamic visualization only changes the graphic representation of the chain results, and does not change the chain definition, the object order, or the access calculation results.

## Relationship Between the Chain and Communication Calculation

The chain object is used to describe the continuous connection relationship between multiple objects, while the performance of a communication link is determined jointly by the transmitting end, the propagation environment, and the receiving end. For a typical communication connection, this can be summarized as:

$$
\mathrm{Transmitter}
\rightarrow
\mathrm{Propagation\ Channel}
\rightarrow
\mathrm{Receiver}
$$

A communication model usually involves, in order:

$$
EIRP
\rightarrow
L_{\mathrm{FS}}
\rightarrow
L_{\mathrm{RF}}
\rightarrow
P_r
\rightarrow
G/T
\rightarrow
C/N_0
\rightarrow
C/N
\rightarrow
E_b/N_0
\rightarrow
BER
$$

where:

- $EIRP$ is the equivalent isotropic radiated power;
- $L_{\mathrm{FS}}$ is the free-space propagation loss;
- $L_{\mathrm{RF}}$ represents RF environment losses such as rain attenuation, atmospheric absorption, and clouds and fog;
- $P_r$ is the received power;
- $G/T$ is the ratio of the receiving antenna gain to the system noise temperature;
- $C/N_0$ is the ratio of the carrier power to the noise power spectral density;
- $C/N$ is the carrier-to-noise ratio;
- $E_b/N_0$ is the ratio of the energy per bit to the noise power spectral density;
- $BER$ is the bit error rate.
