# Number of Accesses

## Definition

Number of Accesses counts the **number of independent access intervals** formed between the analysis object and each coverage resource.

Accesses produced by different resources are counted separately. Even if the access intervals of multiple resources overlap in time, they are not merged into a single access because of the overlap.

For example, if the analysis object forms one access with each of two resources, the total number of accesses is still 2 even if the access of the second resource is completely contained within the access interval of the first resource.

## Parameter Descriptions

### Computation

【Number of Accesses】 supports the following computation methods:

| Computation Method | Meaning | Parameters |
|---|---|---|
| **Avg Per Day** | The total number of accesses divided by the number of days contained in the analysis period, representing the average number of accesses per day. | None |
| **In Span** | Counts the number of accesses whose duration falls within the specified range during the whole analysis period. | **Minimum, Maximum** |
| **In Span Per Day** | The number of accesses that satisfy the specified duration range divided by the number of days contained in the analysis period. | **Minimum, Maximum** |
| **Max Per Day** | The maximum number of accesses among the UTC days. | None |
| **Min Per Day** | The minimum number of accesses among the UTC days. | None |
| **Total** | The total number of all independent accesses within the whole analysis period. | None |

### Minimum, Maximum

They are displayed only when 【Computation】 is 【In Span】 or 【In Span Per Day】.

They are used to limit the access durations that participate in the access count statistics:

$$
T_{\min}
\le
T_{\mathrm{access}}
\le
T_{\max}.
$$

Only accesses whose duration falls within this range are counted.

### Satisfaction Condition

After enabling 【Satisfaction Condition】, you can set a comparison condition and a threshold according to the Number of Accesses statistic.

For example, setting 【Greater Than 0】 means that the satisfaction condition is satisfied only when at least one access that meets the current computation rule occurs.

::: tip Note

- 【Total】 counts all independent accesses and does not merge them because of time overlap between different resources.
- Statistics involving "per day" are all divided by UTC day, that is, from UTC 00:00 to the next UTC 00:00.
- The range in 【In Span】 and 【In Span Per Day】 refers to the **access duration range**, not the range of the instants at which the accesses occur.
:::
