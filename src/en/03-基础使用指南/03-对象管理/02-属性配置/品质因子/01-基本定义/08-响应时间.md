# Response Time

## Definition

Response Time represents the time that must be waited from the current instant to the start of the next coverage interval that satisfies the coverage requirement.

Let the current instant be $t_{\mathrm{cur}}$ and the start of the next coverage interval that satisfies the coverage requirement be $t_{\mathrm{start}}^{(3)}$. Then:

$$
V_{\mathrm{rsp}}
=
t_{\mathrm{start}}^{(3)}
-
t_{\mathrm{cur}}.
$$

![Response Time](../../../../../../zh/03-基础使用指南/03-对象管理/02-属性配置/品质因子/01-基本定义/media/响应时间/image.png)

If the current instant is already within a coverage interval that satisfies the requirement, the response time is 0.

## Parameter Descriptions

### Computation

【Response Time】 supports the following computation methods:

| Computation Method | Meaning | Parameters |
|---|---|---|
| **Mean** | The average response time over the whole analysis period. | **Minimum Multiplicity, End Gap** |
| **Maximum** | The maximum response time over the whole analysis period, which can be used to characterize the worst-case waiting time. | **Minimum Multiplicity, End Gap** |
| **Minimum** | The minimum response time over the whole analysis period; as long as there is an instant that satisfies the coverage requirement, the minimum is usually 0. | **Minimum Multiplicity, End Gap** |
| **Percent Below** | Computes the response time threshold $R$ such that the response time is no greater than $R$ for the specified percentage of time. | **Percentage, Minimum Multiplicity, End Gap** |
| **Percent Below Gaps Only** | Computed only within coverage gaps; computes the response time threshold $R$ such that the response time is no greater than $R$ for the specified percentage of the time within the gaps. | **Percentage, Minimum Multiplicity, End Gap** |

### Percentage

It is displayed only when 【Computation】 is 【Percent Below】 or 【Percent Below Gaps Only】.

Let the entered percentage be $X$ and the computation result be $R$:

- 【Percent Below】: means that for $X\%$ of the whole analysis period
  $$
  V_{\mathrm{rsp}}\le R;
  $$
- 【Percent Below Gaps Only】: performs the same percentile statistic only within uncovered gaps, and does not include the $V_{\mathrm{rsp}}=0$ of already covered instants in the percentage computation.

### Minimum Multiplicity

Sets the minimum number of simultaneously covering resources required for an instant to be judged as "already covered".

Let the minimum multiplicity be $N$. Then only the intervals that satisfy: $
n(t)\ge N
$

are treated as valid coverage intervals and participate in the response time computation.

For example:

- minimum multiplicity 1: wait for the next coverage by at least one resource;
- minimum multiplicity 2: wait for the next simultaneous coverage by at least two resources.

### End Gap

Used to set whether the boundary gap formed at the end of the analysis period, after the last valid coverage, is included in the response time statistics:

- 【Include】: includes the end gap in the computation;
- 【Ignore】: does not use the end gap in the statistics.

For the mean, the maximum, and the percentile statistics, whether the end gap is included may affect the final result, and should be chosen according to how the task requires the analysis period boundary to be handled.

### Satisfaction Condition

When the interface allows it to be enabled, you can set a comparison condition and a threshold according to the response time result.

For example, if you want the response time not to exceed 600 s, you can select an appropriate less-than type condition and set the threshold to 600 s.

::: tip Note
The difference between 【Percent Below】 and 【Percent Below Gaps Only】 is whether instants that are already in a covered state are included in the percentile statistic. The latter counts only the response time within coverage gaps, and is more suitable for evaluating "how long you need to wait when no coverage occurs".
:::
