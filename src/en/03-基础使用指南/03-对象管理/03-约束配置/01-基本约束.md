# Basic Constraints

## Function Description

Basic Constraints filter visibility, communication, or coverage intervals based on the relative geometry between the analysis object and the associated object. By setting geometric conditions such as azimuth, elevation, range, angular rate, altitude, and propagation delay, and by applying line-of-sight, field-of-view, and terrain obstruction checks, you can determine whether two objects satisfy the mission requirements at the current time.

Basic Constraints include the following four categories:

| Constraint Type | Function |
| --- | --- |
| Geometric Parameter Constraints | Determine the relative geometry between objects based on azimuth, elevation, range and their rates, as well as angular rate, altitude, and propagation delay. |
| Line-of-Sight Constraint | Determines whether the line of sight between the analysis object and the associated object is obstructed by the central body. |
| Field-of-View Constraint | Determines whether the associated object is within the sensor's effective field of view. |
| Terrain Mask | Determines whether the line of sight between objects is obstructed by terrain elevation. |

The constraints are independent of one another. The current time satisfies the Basic Constraints only when all enabled constraints are satisfied.

Geometric parameter constraints support **Min** and **Max** values and **Reverse Selection** (exclude accesses that satisfy the specified range and retain only those that do not). When both Min and Max are enabled, the parameter $x$ must satisfy:

$$
x_{\min}\leq x\leq x_{\max}
$$

<Entry meta="Dimension: Angle|Unit: deg, rad, arcSec, arcMin, revs" name="Minimum Elevation" desc="Available only for AreaTarget objects. Specifies the minimum elevation required for the analysis object to observe or access an AreaTarget. Accesses below this angle do not satisfy the constraint." objects="AreaTarget">

<HtmlDemo
  src="../../../../zh/03-基础使用指南/03-对象管理/03-约束配置/media/01-基本约束/min-elevation.html"

Minimum Elevation limits the lowest elevation allowed when the analysis object accesses an AreaTarget. Accesses whose elevation is below this value are removed as a whole, which is equivalent to cutting out a ring of low-elevation sky around the AreaTarget so that only accesses entering from higher angles take part in the subsequent evaluation. Its vertex is at the AreaTarget (its centroid) rather than at the analysis object, and it measures the direction in which the AreaTarget looks toward the analysis object.

</Entry>

</Entry>

<Entry name="Line of Sight" desc="Determines whether the line of sight between the analysis object and the associated object is obstructed by the Earth or another central body." objects="Receiver,GroundVehicle,Sensor,Missile,Facility,Transmitter,Aircraft,CoverageDefinition,LaunchVehicle,SatelliteCollection,Ship,Submarine,AreaTarget,Satellite,SatelliteSystem,Planet">

The Line of Sight constraint analyzes cases in which central body obstruction makes two objects invisible to one another and evaluates the line-of-sight quality between them. Its output value is calculated differently depending on the type of object to which the constraint belongs.

For the computational models for fixed objects, moving objects, and objects on the surface of a celestial body, as well as the treatment of negative elevation, see [Line-of-Sight Constraint](../../../04-理论基础/02-约束配置/01-基本约束.md#line-of-sight-constraint).

</Entry>

<Entry name="Field of View" desc="Determines whether the associated object is within the sensor's effective observation range." objects="Sensor,Missile,SatelliteCollection">

The field of view is defined by the sensor's characteristic angles. The constraint is satisfied at the current time only when the target direction is inside the sensor's field of view.

</Entry>

<Entry name="Terrain Mask" desc="Determines whether the line of sight between objects is obstructed by actual terrain, accounting for the effects of terrain elevation on visibility and coverage." objects="Receiver,GroundVehicle,Sensor,Missile,Facility,Transmitter,Aircraft,CoverageDefinition,LaunchVehicle,SatelliteCollection,Ship,Submarine,Satellite,SatelliteSystem,Planet">

::: tip Terrain Data Configuration
- Before enabling **Terrain Mask**, configure the terrain data to be used in the analysis under **[Scenario Object Properties - Terrain](../../02-场景管理/03-场景属性配置/02-基本/03-地形.md)**.

- The terrain data used in constraint calculations is independent of the terrain visualization configured in a 3D view. Even if terrain is displayed in a 3D view, that terrain data is not necessarily used in constraint calculations.

- To display terrain in a 3D view, configure the corresponding **terrain visualization data** separately in each **3D View**.
:::

</Entry>
