# Introduction and Configuration

## Introduction

The Octave SDK lets you write scripts in your own Octave environment and interact with ATK over a TCP network connection, enabling automated operations such as scenario building, parameter setting and simulation running.

Octave itself does not provide a dedicated communication library. Instead, it calls the ATK Java communication library through its **built-in Java interface**: the script first imports `ATKConnectJava.jar`, then loads its native dynamic library, and finally creates a `com.atk.connect.ATKConnectJavaModule` object and calls its interface methods. Therefore, the Octave interface signatures are exactly the same as those of the [Java SDK](../4-Java/1-简介与配置.md), which suits scenarios where you already have an Octave environment and want to control ATK with `.m` scripts.

::: tip Choosing a Development Method
For a detailed comparison of the development methods, refer to the [Connect Mode Overview](../../../README.md#development-method-comparison).
:::

## Environment and Configuration

### Octave Environment

You need to download and install the Octave environment yourself. We recommend **Octave 5.2.0 or later**. With an older version, the built-in Java interface may be unavailable and the script will not be able to load the ATK communication library.

### Java Environment

Because Octave calls the ATK communication library through its built-in Java interface, a Java environment must be installed separately in addition to Octave. We recommend **Java 1.7.0 or later**; for the installation and environment variable configuration method, refer to [Java Installation and Environment Configuration](../../../../4-二次开发COMPONENT模式/3-Java操作流程/1-Java安装与环境配置.md).

::: warning Note
Before sending commands with the Octave SDK, you must open the ATK software (no scenario needs to be open). To create a new scenario, close any scenario that is already open.
:::

### Communication Library Files

Octave reuses the Java communication library, which is shipped with the installation package and located in the **root directory of the installation package**:

<PathViewer :relative-paths="sdkFiles" />

- <PathCopy :entry="javaJar" />: the Java interface class library, containing classes such as `com.atk.connect.ATKConnectJavaModule`; it is imported by the script through `javaaddpath`.
- <PathCopy :entry="javaDll" />: the JNI native dynamic library, loaded by `ATKLibraryLoader`.
- <PathCopy :entry="connectorDll" />: the low-level communication dynamic library, which `ATKConnectJava.dll` depends on.
- <PathCopy :entry="octaveTest" />: the official example source code, containing the complete implementation of the fast orbit transfer case.

::: info Linux (Kylin) Environment
Under the Kylin environment, the directory containing the communication library is the same as on Windows — the **root directory of the ATK installation package** — only the file extensions differ: `ATKConnectJava.dll` and `ATKConnectorDll.dll` correspond to `libATKConnectJava.so` and `libATKConnectorDll.so` on Kylin; `ATKConnectJava.jar` is platform-independent and has the same name on both platforms.
:::

### Configuration Steps

1. Set the root directory of the installation package as the current path of Octave. All three library files are already in that directory, so there is no need to copy them elsewhere; if you use a self-created working directory, copy the three files above into it first.

2. Load the ATK communication library and create the interface object in the script:

```matlab
if(ispc())
	jarPath = [pwd,'\ATKConnectJava.jar'];
elseif(isunix())
	jarPath = [pwd,'/ATKConnectJava.jar'];
end
if ~any(strcmp(jarPath,javaclasspath()))
	javaaddpath(jarPath);
	javaMethod('loadLibrary', 'ATKLibraryLoader');
end
ATKConnectJavaModule = javaObject('com.atk.connect.ATKConnectJavaModule');
```

::: warning Note
- `ATKConnectJava.dll` and `ATKConnectorDll.dll` must be located in the same directory as `ATKConnectJava.jar`, otherwise loading the dynamic library may fail.
- The script reads `ATKConnectJava.jar` from the **current path** (`pwd`), so make sure the current path has been switched to the directory containing the library files before running.
:::

## Usage

After completing the configuration above, you can call the three core APIs in your script to control ATK. The basic flow is as follows:

```matlab
% 1. Load the ATK Java communication library
if(ispc())
	jarPath = [pwd,'\ATKConnectJava.jar'];
elseif(isunix())
	jarPath = [pwd,'/ATKConnectJava.jar'];
end
if ~any(strcmp(jarPath,javaclasspath()))
	javaaddpath(jarPath);
	javaMethod('loadLibrary', 'ATKLibraryLoader');
end
ATKConnectJavaModule = javaObject('com.atk.connect.ATKConnectJavaModule');

% 2. Establish the connection to ATK
conID = ATKConnectJavaModule.atkOpen("127.0.0.1", 6655);

% 3. Send a command (example: create a new scenario)
ATKConnectJavaModule.atkConnect(conID, 'New', '/ Scenario MyScenario', "");

% 4. Close the connection
ATKConnectJavaModule.atkClose(conID);
```

::: info Note
Octave reuses the Java interface at the underlying layer and has no default parameters, so the IP and port of `atkOpen` must be passed explicitly; the 4th parameter of `atkConnect` is a reserved parameter, so just pass the empty string `""`. For details, see [Core API](./2-核心API.md).
:::

For detailed API parameter descriptions, see [Core API](./2-核心API.md); for a complete example, see [Complete Example](./3-完整示例.md).
