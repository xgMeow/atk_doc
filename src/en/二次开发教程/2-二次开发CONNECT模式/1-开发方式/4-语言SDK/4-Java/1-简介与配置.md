# Introduction and Configuration

## Introduction

The Java SDK is the Java communication library provided by ATK. It lets you write programs in your own Java development environment and interact with ATK over a TCP network connection, enabling automated operations such as scenario building, parameter setting and simulation running.

As one of the core development methods in Connect mode, the Java SDK wraps the ATK low-level communication dynamic library into the `com.atk.connect.ATKConnectJavaModule` class through JNI and exposes static methods externally. It suits scenarios where you need to integrate ATK functionality into a Java project, or to connect with an existing Java engineering system.

::: tip Choosing a Development Method
For a detailed comparison of the development methods, refer to the [Connect Mode Overview](../../../README.md#development-method-comparison).
:::

## Environment and Configuration

### Java Environment

You need to download and install the Java environment yourself. We recommend JDK 8 or later, and you should complete the configuration of the `JAVA_HOME` and `Path` environment variables. For the configuration method, refer to [Java Installation and Environment Configuration](../../../../4-二次开发COMPONENT模式/3-Java操作流程/1-Java安装与环境配置.md).

::: warning Note
Before sending commands with the Java SDK, you must open the ATK software (no scenario needs to be open). To create a new scenario, close any scenario that is already open.
:::

### Communication Library Files

The ATK Java communication library is shipped with the installation package; **the interface files and library files are all located in the root directory of the installation package**:

<PathViewer :relative-paths="sdkFiles" />

- <PathCopy :entry="javaJar" />: the Java interface class library, containing classes such as `com.atk.connect.ATKConnectJavaModule`; it must be referenced both at compile time and at run time.
- <PathCopy :entry="javaDll" />: the JNI native dynamic library, loaded by `System.loadLibrary("ATKConnectJava")`.
- <PathCopy :entry="connectorDll" />: the low-level communication dynamic library, which `ATKConnectJava.dll` depends on.
- <PathCopy :entry="javaTest" />: the official example source code, containing the complete implementation of the fast orbit transfer case; it must be placed in the directory matching its package name.

::: info Linux (Kylin) Environment
Under the Kylin environment, the directory containing the communication library is the same as on Windows — the **root directory of the ATK installation package** — only the file extensions differ: `ATKConnectJava.dll` and `ATKConnectorDll.dll` correspond to `libATKConnectJava.so` and `libATKConnectorDll.so` on Kylin; `ATKConnectJava.jar` is platform-independent and has the same name on both platforms.
:::

### Configuration Steps

1. Create a working directory and copy <PathCopy :entry="javaJar" />, <PathCopy :entry="javaDll" /> and <PathCopy :entry="connectorDll" /> from the root directory of the installation package into it

2. Under the working directory, create the subdirectory `com\atk\test` according to the package name, and copy the example source code <PathCopy :entry="javaTest" /> into it

3. Load the dynamic library and import the interface methods in your code:

```java
import static com.atk.connect.ATKConnectJavaModule.atkOpen;
import static com.atk.connect.ATKConnectJavaModule.atkConnect;
import static com.atk.connect.ATKConnectJavaModule.atkClose;

public class ATKConnectJavaTest {
  static {
    try {
      // Load the ATKConnectJava dynamic library
      System.loadLibrary("ATKConnectJava");
    } catch (UnsatisfiedLinkError e) {
      System.err.println("load dll failed\n" + e);
      System.exit(1);
    }
  }
}
```

4. Compile and run in the working directory (Windows platform):

```bash
javac -cp ATKConnectJava.jar -encoding utf-8 com/atk/test/ATKConnectJavaTest.java
java -cp ".;ATKConnectJava.jar" com/atk/test/ATKConnectJavaTest
```

::: warning Note
- `ATKConnectJava.dll` and `ATKConnectorDll.dll` must be located in the working directory, or in a directory covered by `java.library.path`; otherwise `System.loadLibrary` throws an `UnsatisfiedLinkError`.
- On the Linux platform, `:` is used as the class path separator; the command is `java -cp ".:ATKConnectJava.jar" com.atk.test.ATKConnectJavaTest`.
- If the source code contains Chinese characters, save it as UTF-8 without BOM and keep the `-encoding utf-8` in the compile command.
:::

## Usage

After completing the configuration above, you can call the three core APIs in your code to control ATK. The basic flow is as follows:

```java
// 1. Establish the connection to ATK
int conID = atkOpen("127.0.0.1", 6655);

// 2. Send a command (example: create a new scenario)
atkConnect(conID, "New", "/ Scenario MyScenario", "");

// 3. Close the connection
atkClose(conID);
```

::: info Note
Java has no default parameters, so the IP and port of `atkOpen` must be passed explicitly; the 4th parameter of `atkConnect` is a reserved parameter, so just pass the empty string `""`. For details, see [Core API](./2-核心API.md).
:::

For detailed API parameter descriptions, see [Core API](./2-核心API.md); for a complete example, see [Complete Example](./3-完整示例.md).
