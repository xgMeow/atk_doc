# Introduction and Configuration

## Introduction

The Matlab SDK lets you write scripts in your own Matlab environment and interact with ATK over a TCP network connection, enabling automated operations such as scenario building, parameter setting and simulation running.

Matlab itself does not provide a dedicated communication library; instead, it calls the ATK Java communication library through its **built-in Java interface**: the script first imports `ATKConnectJava.jar`, then loads its native dynamic library, and finally creates a `com.atk.connect.ATKConnectJavaModule` object and calls its interface methods. Therefore the Matlab interface signatures are exactly the same as those of the [Java SDK](../4-Java/1-简介与配置.md), which suits scenarios where you already have a Matlab environment and want to control ATK with `.m` scripts.

::: tip Choosing a Development Method
For a detailed comparison of the development methods, refer to the [Connect Mode Overview](../../../README.md#development-method-comparison).
:::

## Environment and Configuration

### Matlab Environment

You need to download and install a Matlab environment yourself. **Matlab R2015b or later** is recommended (R2015b / R2021b / R2024b have all been verified).

### Java Environment

Because Matlab calls the ATK communication library through its built-in Java interface, a separate Java environment is required in addition to Matlab. **Java 1.7.0 or later** is recommended; for how to install it and configure the environment variables, see [Java Installation and Environment Configuration](../../../../4-二次开发COMPONENT模式/3-Java操作流程/1-Java安装与环境配置.md).

::: warning Note
Before sending commands with the Matlab SDK, you must open the ATK software (no scenario needs to be open). To create a new scenario, close any scenario that is already open.
:::

### Communication Library Files

Matlab reuses Java's communication library, which is shipped with the installation package and located in the **root directory of the installation package**:

<PathViewer :relative-paths="sdkFiles" />

- <PathCopy :entry="javaJar" />: the Java interface class library, containing classes such as `com.atk.connect.ATKConnectJavaModule`, imported by the script with `javaaddpath`.
- <PathCopy :entry="javaDll" />: the JNI native dynamic library, loaded by `ATKLibraryLoader`.
- <PathCopy :entry="connectorDll" />: the low-level communication dynamic library, which is depended on by `ATKConnectJava.dll`.
- <PathCopy :entry="matlabTest" />: the official example source code, containing the complete implementation of the fast orbit transfer case.

::: info Linux (Kylin) environment
Under the Kylin environment, the directory containing the communication library is the same as on Windows — the **root directory of the ATK installation package** — only the file suffixes differ: `ATKConnectJava.dll` and `ATKConnectorDll.dll` correspond to `libATKConnectJava.so` and `libATKConnectorDll.so` under Kylin; `ATKConnectJava.jar` is platform independent and has the same name on both platforms.
:::

::: info Legacy approach
The early MEX-based Matlab communication library (`atkOpen.m`, `atkConnect.m`, `atkClose.m`, `atkExecuteCommand.m`, `mexATKConnect.mexw64`, etc.) is located under `IntegratingWithATK\connect\Matlab`; you need to `addpath` it to the Matlab search path first and then call the functions such as `atkOpen` and `atkConnect` directly. That approach has been superseded by the Java interface approach described above and is not recommended for new projects. The rest of this page is about the Java interface approach.
:::

### Configuration Steps

1. Set the root directory of the installation package as the current path of Matlab. The three library files are already in that directory, so there is no need to copy them; if you use a working directory of your own, copy the three files above into it first.

2. Load the ATK communication library in the script and create the interface object:

```matlab
if(ispc())
    jarPath = [pwd,'\ATKConnectJava.jar'];
elseif(isunix())
    jarPath = [pwd,'/ATKConnectJava.jar'];
end
if ~any(strcmp(jarPath,javaclasspath()))
    javaaddpath(jarPath);
    javaMethod('loadLibrary', 'ATKLibraryLoader');
end
ATKConnectJavaModule = javaObject('com.atk.connect.ATKConnectJavaModule');
```

::: warning Note
- `ATKConnectJava.dll` and `ATKConnectorDll.dll` must be located in the same directory as `ATKConnectJava.jar`; otherwise loading the dynamic library may fail.
- The script reads `ATKConnectJava.jar` from the **current path** (`pwd`), so before running, make sure the current path has been switched to the directory containing the library files.
- The default encoding of Matlab for `.m` files is GBK. If the Chinese comments in the script appear garbled, adjust the file encoding of the script and save it again.
:::

## Usage

After completing the configuration above, you can call the three core APIs in your script to control ATK. The basic flow is as follows:

```matlab
% 1. Load the ATK Java communication library
if(ispc())
    jarPath = [pwd,'\ATKConnectJava.jar'];
elseif(isunix())
    jarPath = [pwd,'/ATKConnectJava.jar'];
end
if ~any(strcmp(jarPath,javaclasspath()))
    javaaddpath(jarPath);
    javaMethod('loadLibrary', 'ATKLibraryLoader');
end
ATKConnectJavaModule = javaObject('com.atk.connect.ATKConnectJavaModule');

% 2. Establish the connection to ATK
conID = ATKConnectJavaModule.atkOpen('127.0.0.1', 6655);

% 3. Send a command (example: create a new scenario)
ATKConnectJavaModule.atkConnect(conID, 'New', '/ Scenario MyScenario', '');

% 4. Close the connection
ATKConnectJavaModule.atkClose(conID);
```

::: info Note
Matlab reuses the Java interface underneath, which has no default parameters, so the IP and port of `atkOpen` must be passed explicitly; the 4th parameter of `atkConnect` is a reserved parameter, and you can simply pass an empty string `''`. See [Core API](./2-核心API.md) for details.
:::

For detailed API parameter descriptions, see [Core API](./2-核心API.md); for a complete example, see [Complete Example](./3-完整示例.md).
