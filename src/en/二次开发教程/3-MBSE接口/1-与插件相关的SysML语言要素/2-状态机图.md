# State Machine Diagram

A state machine diagram is one of the three SysML diagrams that can describe the dynamic behavior of a system. It can display various states, and four types of events can be specified to trigger transitions between states in a running system. SysML can also use orthogonal regions to model state-based concurrent behavior. The main elements it contains are as follows:

- State: A condition or situation during the life cycle of an object in which the object satisfies certain conditions, performs certain activities, or waits for certain events. As shown in the following figure:

    ![State](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image.png)

    Initial and final states: The initial state of a state machine diagram is called the initial pseudostate and is represented by a solid circle; this state transitions to the first real state. The final state of a state machine diagram is shown as concentric circles. As shown in the following figure:


    ![Initial and Final States](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-1.png)


- Transition: Represents a change from one state to another state. As shown in the following figure:

    ![Transition](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-2.png)

- An event is an element defined in the system model; it defines the types of events that can trigger behavior in the actual system. SysML defines the following four types of events, as shown in the following figure:

    - Signal event: Can be understood as sending and receiving signals
    - Call event: Corresponds to a procedure call to an operation
    - Time event: A timed event that occurs after a specified time has elapsed, either relative time (after) or absolute time (at)
    - Change event: A change event occurs whenever a specified condition is satisfied

    ![Event](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-3.png)


- Action: An executable atomic computation that cannot be interrupted, including operation calls, the creation or destruction of objects, or sending signals to objects. An action may cause a change in the state of the model or the return of a value.

    - Entry action: The first behavior executed upon entering that state. As shown in the following figure:

    ![Entry Action](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-4.png)

    - Exit action: The last behavior executed before leaving that state. As shown in the following figure:

    ![Exit Action](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-5.png)

- Composite state: Has substates, as shown in the following figure:

    ![Composite State](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/2-状态机图/image-6.png)

- History state: A pseudostate whose purpose is to remember the substate that was active when the composite state was exited, so that when the composite state is entered again, that substate can be entered directly rather than starting from the initial state.

State machine diagrams are typically used to describe the state-related behavior of an object. An object responds to events according to the state it is in. A state machine diagram is well suited as a detailed design artifact (that is, the input for development), so it is commonly used in system design and simulation/code generation.
