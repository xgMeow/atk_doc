# Module Definition Diagram

The diagram type abbreviation of a module definition diagram is BDD. It is the most common diagram in SysML, used to define the features of blocks and the relationships between blocks.

## Main Elements

A block is the basic unit in the SysML structure. You can use blocks to create models for any entity type of interest inside the system or in the environment outside the system. A block represents a type or category, not a specific instance. As shown in the following figure:

![Block](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image.png)

The properties of a block fall into two major categories: structural properties and behavioral properties. Structural properties include part properties, reference properties, value properties, constraint properties, flow properties, and ports; behavioral properties include operations and signal receptions. They represent the state of the system and the behaviors that the system may exhibit. In a module definition diagram, the property categories of a block are placed in separate compartments.

## Block Properties

- Structural property: A part property represents the internal structure of a block. In other words, a block is composed of parts, which expresses a relationship of ownership and represents the internal structure of the block. As shown in the following figure:

    ![Part Property](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-1.png)

- Reference property: Represents a structure external to the block. It may reside inside another block; this is not an ownership relationship but a "needs" relationship, providing functions, data, or information for the current block. As shown in the following figure:

    ![Reference Property](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-2.png)

- Value property: Can represent a number (of some type), a Boolean value, or a string. It is most commonly assigned a number. As shown in the following figure:

    ![Value Property](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-3.png)


- Constraint property: Generally represents a mathematical relationship, an equation or an inequality. The type of a constraint property is a constraint block, and a constraint block contains constraint relationships that can be reused. As shown in the following figure:

    ![Constraint Property](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-4.png)

- Port: A special kind of part that represents the exchange of information; it is used specifically to exchange information with the outside. There are three kinds of ports: full ports, proxy ports, and flow ports. As shown in the following figure:

    A full port can be regarded as an independent part; a full port directly processes the information it receives and outputs the processed information.

    A proxy port does not have the capability to process information itself; instead, it is bound to an internal block through a binding connector.

    Flow ports are directional; the directions of a flow property are "in", "out", or "inout".

    ![Port](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-5.png)

- Behavioral property:

    Operation: Represents the behavior executed when a client calls the block. It is triggered by a call event. An operation represents a synchronous action, but its implementation needs to be described through the behavior diagram of the corresponding method.

    Reception: A method by which a block receives and processes a signal. A reception always corresponds to a signal defined somewhere in the model, and its parameters correspond to the properties of the signal. A reception is an asynchronous behavior; the client that sends the signal does not wait for a reply.

## Relationships in the Module Definition Diagram

There are three main types of relationships between blocks: association, generalization, and dependency. An association is a notation for expressing relationships among system structures such as blocks, reference properties, and part properties. An association defaults to a reference association. Within association relationships, a distinction must be made between composite associations and shared associations.

- Composite association: Represents a structural decomposition. The block instance at the composite end is formed by combining some block instances at the part ends; it can be understood as a "contains" relationship, and a part can belong to only one composite. In a composite association notation, an arrow indicates one-way navigation, while no arrow indicates two-way navigation. As shown in the following figure:

    ![Composite Association](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-6.png)

- Generalization: Represents an inheritance relationship between two elements: a more general element (supertype) and a more specific element (subtype). Read from the subtype to the supertype, this reads as "... is a ...". Generalization is transitive and propagates through the generalization relationship down to the final level. In addition, generalization means that the subtype inherits all the features of the supertype and may also have other features that the supertype does not have. As shown in the following figure:


    ![Generalization](../../../../zh/二次开发教程/3-MBSE接口/1-与插件相关的SysML语言要素/media/1-模块定义图/image-7.png)

- Dependency: Means that one element in the model, the client, depends on another element in the model, the supplier. When the supplier element changes, the client element may also need to change. Establishing a dependency determines the traceability between the two.
